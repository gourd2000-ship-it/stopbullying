# 데이터베이스(DB) 연동 기능 요구사항 정의서 (PRD)

본 문서는 '마음샘' 학교폭력 상담 챗봇 프로젝트의 상담 기록 저장 방식을 로컬 스토리지에서 실제 데이터베이스(DB)로 전환하기 위한 제품 요구사항 정의서(PRD)입니다.

---

## 1. 프로젝트 개요 및 목적
* **개요**: 기존 MVP 버전의 상담 기록은 사용자의 개별 웹 브라우저(`localStorage`)에만 저장되어 타 기기에서는 조회가 불가능했습니다.
* **목적**: 상담 기록을 중앙 데이터베이스(DB)로 이전하여, 상담 교사(관리자)가 어떤 기기에서 접속하든 전체 학생들의 상담 이력을 통합 조회 및 관리할 수 있도록 합니다.

---

## 2. 사용자 시나리오 (User Story)

### 2.1 학생 (상담 사용자)
* **시나리오**: 학생은 상담을 진행하고 [상담 종료] 버튼을 누르거나 대화가 마무리되었을 때 지연 시간 없이 안전하게 상담 요약 결과와 대화 기록이 서버로 전송되어 저장되어야 합니다.
* **요구사항**: 저장 과정에서 UI가 멈추거나 튕기는 현상이 없어야 합니다.

### 2.2 상담 교사 (관리자)
* **시나리오**: 교사는 로그인 페이지(`/admin/login`)에서 지정된 비밀번호를 입력하고 접속합니다. 접속 후 대시보드에서 전송된 모든 학생들의 상담 기록을 시간 순으로 확인하고 상태 변경 및 메모 추가를 수행합니다.
* **요구사항**: 
  * 다른 기기나 브라우저에서 들어온 최신 상담글이 목록에 즉시 노출되어야 합니다.
  * 데이터를 조회해오는 동안 '로딩 중' 표시가 제공되어 화면이 깨져 보이지 않아야 합니다.

---

## 3. 기능적 요구사항 (Functional Requirements)

### 3.1 공통 기능 (기반 모듈)
* **DB 커넥터**: 백엔드 서버가 구동될 때 외부 클라우드 DB(예: Supabase)와의 연결 상태를 안정적으로 유지해야 합니다.
* **단일 비밀번호 인증 미들웨어 (보안)**:
  * 백엔드 API 중 관리자용 데이터 조회 및 수정 엔드포인트는 호출 시 반드시 요청 헤더(`x-admin-password`)에 비밀번호를 포함해야 합니다.
  * 서버는 헤더값과 서버 환경 변수(`process.env.ADMIN_PASSWORD`)가 매칭되는 경우에만 접근을 허용하고, 불일치 시 `401 Unauthorized`를 반환합니다.

### 3.2 개별 기능 1: 학생 상담 기록 저장
* **API 사양**: `POST /api/consultations`
  * Request Body: `{ nickname, summary, chatHistory, isEmergency }`
  * Response: 성공 시 `{ success: true, id: "생성된UUID" }`
* **프론트엔드 연동**: 대화 종료 이벤트 발생 시 위의 API를 비동기 호출합니다.

### 3.3 개별 기능 2: 관리자 대시보드 조회 및 수정
* **API 사양**:
  * `GET /api/consultations`: 전체 상담 목록을 최신순으로 정렬하여 반환 (비밀번호 검증 필수).
  * `GET /api/consultations/:id`: 개별 상담의 전체 대화 내용 및 상세 요약 데이터를 반환 (비밀번호 검증 필수).
  * `PATCH /api/consultations/:id`: 상담 상태(status), 읽음 여부(isRead), 교사 메모(adminMemo)를 업데이트 (비밀번호 검증 필수).
* **프론트엔드 비동기 대응**:
  * API 데이터 로딩 시간 동안 사용자에게 스피너 또는 '로딩 중...' 텍스트를 제공합니다.
  * 비밀번호 검증이 실패한 경우 로컬스토리지의 비밀번호를 파기하고 로그인 화면(`/admin/login`)으로 강제 이동(Redirect)시킵니다.

---

## 4. 데이터베이스 스키마 설계

Supabase(PostgreSQL) 기준으로 다음 사양의 테이블을 구성합니다.

| 컬럼명 | 데이터 타입 | 제약 조건 | 설명 |
| :--- | :--- | :--- | :--- |
| **id** | UUID | PRIMARY KEY, Default: gen_random_uuid() | 고유 식별자 |
| **created_at** | TIMESTAMP WITH TIME ZONE | NOT NULL, Default: now() | 상담 생성 일시 |
| **nickname** | VARCHAR(50) | NOT NULL | 학생 별명 |
| **status** | VARCHAR(20) | NOT NULL, Default: '새 상담' | 상담 상태 ('새 상담', '확인 중', '상담 필요', '조치 완료', '보류') |
| **risk_level** | VARCHAR(10) | NOT NULL, Default: '낮음' | 위험도 ('낮음', '보통', '높음', '긴급') |
| **is_read** | BOOLEAN | NOT NULL, Default: false | 관리자 확인 여부 |
| **is_emergency**| BOOLEAN | NOT NULL, Default: false | 긴급 상황 여부 |
| **summary** | JSONB | NOT NULL | AI가 추출한 요약 데이터 객체 전체 |
| **chat_history**| JSONB | NOT NULL | 학생-봇-시스템 전체 대화 배열 |
| **admin_memo** | TEXT | Default: '' | 교사 작성 메모 |

---

## 5. 비기능적 요구사항 (Non-Functional Requirements)
* **보안**: 
  * 외부로 DB 연결 비밀번호 및 마스터 API Key가 노출되어서는 안 됩니다. (서버 사이드 환경변수로만 취급)
  * 프론트엔드와 백엔드 간 통신은 암호화된 채널(HTTPS)로만 진행되어야 비밀번호 헤더의 도청을 예방할 수 있습니다.
* **성능 및 사용자 경험**: 
  * 상담 저장 요청은 비동기로 백그라운드 처리되어 학생 화면에 대기 지연을 주지 않아야 합니다.
  * 관리자 목록 조회 성능 향상을 위해 인덱스 설정을 검토합니다 (`created_at` 정렬용).
